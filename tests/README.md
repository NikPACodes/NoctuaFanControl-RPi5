# Noctua Fan Control — Тестирование (pytest)
## Назначение
Каталог `tests/` содержит автоматические тесты системы управления вентилятором 
__Noctua NF-A4x20 5V PWM__ для Raspberry Pi 5.

Тесты проверяют корректность алгоритмов, обработку ошибок, работу конфигурации, 
калибровку RPM и взаимодействие компонентов проекта.

> Все тесты выполняются __без доступа__ к физическим `GPIO`, 
> не управляют реальным вентилятором и не требуют `sudo`.

## 2. Установка зависимостей
Для тестирования требуется `Python` и `pytest`.

> Рекомендуется использовать виртуальное окружение `.venv`.
>
> Создание и активация виртуального окружения:
>```bash
>python3 -m venv .venv
>source .venv/bin/activate
>```

Установка pytest:
```bash
python -m pip install pytest
```

Проверка установленной версии:
```bash
python -m pytest --version
```

> Тестам не требуется установленный `lgpio`

## 3. Запуск всех тестов

## 4. Маркеры pytest
Маркеры позволяют запускать определённые категории тестов независимо друг от друга.

### config — Конфигурация
```bash
python -m pytest -m config -v
```
Проверяет:
1. Валидацию кривых `CPU`/`NVMe` и защиту от `NaN`.
2. Запрет сохранения некорректного LEVEL.
3. `AUTO`/`MANUAL`, резервную копию и атомарную запись.
4. Блокировку конкурентных изменений конфигурации.
5. Запрет одновременного получения файловой блокировки 
двумя экземплярами daemon в одном каталоге проекта.
6. Отклонение некорректной конфигурации при hot-reload 
с сохранением последних рабочих настроек.


### policy — Управление вентилятором
```bash
python -m pytest -m policy -v
```
Проверяет:
1. Интерполяцию `PWM` и приоритет `CPU`/`NVMe`.
2. Гистерезис и минимальную выдержку по параметрам текущего `config.json`.
3. Усреднение NVMe и потерю температурного датчика. 
4. Режим `MANUAL` и приоритет аварийного охлаждения. 
5. Расчёт `TACH`/`RPM` и аварийную реакцию. 
6. Start-boost при переходе из `PWM=0`. 
7. Сравнение `RPM` с baseline и предупреждение об обслуживании.


### calibration — Калибровка RPM
```bash
python -m pytest -m calibration -v
```
Проверяет:
1. Запрет калибровки без работающего daemon. 
2. Отмену калибровки при несовпадении `PWM`. 
3. Сохранение baseline при отсутствии `RPM`. 
4. Успешную калибровку, сохранение baseline 
и восстановление исходного режима `AUTO`/`MANUAL`.


### runtime — Мониторинг и daemon
```bash
python -m pytest -m runtime -v
```
Проверяет:
1. Определение устаревшего `status.json`.
2. Работу CLI и read-only мониторинга CPU/HAT.
3. Три цикла управления с подменённым GPIO.


### hardware — Программный интерфейс аппаратного PWM RP1 (моделирование)
```bash
python -m pytest -m hardware -v
```
Проверяет:
1. Обнаружение `PWM0 RP1` по идентификатору устройства.
2. Отказ при отсутствии нужного PWM-контроллера.
3. Запрет перехвата активного PWM без подтверждения состояния.
4. Сохранение `enable=1` при `PWM=0` и после `close()`.
5. Изменение периода и duty_cycle.
6. Отклонение инверсной полярности.
7. Ограничение аппаратного backend на `GPIO18`.
8. Определение GPIO-чипа `RP1` для `TACH`.
9. Отклонение неправильного режима pinmux.
10. Принятие активного `PWM` при подтверждённых period/duty.

Все проверки выполняются на временных файлах или с подменённым
выводом системных команд.

Реальная частота `PWM`, электрические уровни, непрерывность сигнала
и работа вентилятора этими тестами не подтверждаются.

## 6. Изоляция GPIO
Тесты предназначены для безопасного запуска на обычном компьютере и Raspberry Pi.

В `conftest.py` используются:
- `FakePWM` — имитация PWM-выхода.
- `FakeTACH` — имитация тахометрического входа.
- `FakeFactory` — имитация GPIO-фабрики.
- `project` — фикстура с временной конфигурацией.

Аппаратные модули должны подменяться __до импорта `noctua_daemon.py`__.

Тесты не должны:
- открывать физические `GPIO`;
- изменять `PWM` работающего вентилятора;
- записывать данные в рабочий `config.json`;
- запускать системный сервис управления Noctua;
- требовать `sudo`.

Для операций записи используются временные каталоги, предоставляемые `tmp_path`.


### Независимость тестов от пользовательских настроек
Тесты используют актуальный `config.json` как исходный набор параметров. 
Фикстура `project` копирует конфигурацию во временный каталог pytest.

Изменение допустимых `CPU`/`NVMe` LEVEL, `PWM`, гистерезиса, периода выдержки, 
коэффициента TACH и других параметров не должно требовать изменения ожидаемых результатов тестов.

Ожидаемые значения `PWM` рассчитываются независимой функцией `reference_pwm()`, 
которая не вызывает `daemon.interp_pwm()`.

Для проверки аварийных ситуаций некоторые тесты намеренно задают 
фиксированные искусственные значения в памяти контроллера или во временной конфигурации.  
Это позволяет гарантировать прохождение конкретных веток алгоритма независимо от пользовательских настроек.

Отдельная CLI-проверка `fanctl.py settings` запускается как подпроцесс 
и использует реальный `config.json` проекта только для чтения.

> Успешное прохождение тестов не гарантирует, что настройки прошедшие программную валидацию  физически безопасны.

## 7. Ограничения автоматических тестов
Успешный результат pytest подтверждает выполнение проверенных программных сценариев, 
но не является полной аппаратной проверкой Raspberry Pi 5.

В частности, автоматические тесты не подтверждают:
- фактическую частоту и полярность `PWM` на `GPIO18`;
- достоверность `RPM`, рассчитанных по реальному сигналу `TACH`;
- запуск вентилятора при малом `PWM`;
- восстановление вращения после физической остановки;
- непрерывность PWM-сигнала при перезапуске daemon;
- доступность и принадлежность `RPM` штатного `CPU`/`HAT` вентилятора;
- тепловую эффективность охлаждения при реальной нагрузке.

Отдельные программные сценарии также могут оставаться непокрытыми.  
Результат `passed` относится только к проверкам, реализованным в текущем наборе тестов.  

Аппаратные испытания выполняются отдельно, с записью условий, исходных показаний и результатов.
